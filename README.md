# 基于 SPLADE 改良的 RAG 知识库问答系统

基于 FastAPI + LangChain + Ollama 搭建的私有化本地 RAG 问答平台，采用「稠密向量 + SPLADE 稀疏语义 + Reranker 精排」的三级检索架构，支持长短双记忆机制与 SSE 流式输出，低幻觉、高准确率。

## ✨ 项目亮点

1. **三级混合检索架构**：bge-m3 稠密向量深层语义召回 + SPLADE 稀疏语义检索 + bge-reranker 精排，相比传统 BM25 + 向量方案显著提升转述、同义词、口语化场景的召回准确率
2. **长短双记忆体系**：短期会话记忆（内存级）+ 长期持久化记忆（向量库），会话间记忆严格隔离，支持独立清空
3. **SSE 流式输出**：前端实时逐字渲染回答，原生支持 Markdown 格式与参考来源溯源展示
4. **强约束提示词工程**：刚性规则限定回答范围，仅基于知识库与会话历史作答，大幅降低大模型幻觉
5. **增量文档入库**：自动识别新增 PDF 文件，内置中文文本清洗，增量写入向量库，无需全量重建
6. **完全本地化部署**：所有模型与数据均运行在本地，无数据外泄风险，支持离线环境使用

## 🚀 快速启动

### 前置环境

1. 本地已安装 **Ollama**，并提前拉取所需模型：
```
ollama pull bge-m3
ollama pull deepseek-r1:14b
```
2. Python 3.10+ 运行环境

### 1. 安装依赖

```
pip install -r requirements.txt
```

> 
> 已内置 HuggingFace 国内镜像源，模型下载无需额外配置代理

### 2. 知识库向量化入库

1. 将需要问答的 PDF 文档放入 `docs/` 文件夹
2. 执行入库脚本：
```
python ingest.py
```
   - 自动识别新增文件，跳过已入库文档
   - 内置中文文本清洗逻辑，自动去除 PDF 提取产生的字间空格与冗余换行

### 3. 启动后端服务

```
python sse_server.py
```

服务启动后会自动完成：

- 加载大模型、向量库、SPLADE 稀疏检索索引、重排序模型
- 内存构建全量文档稀疏向量索引
- 监听 `0.0.0.0:8000` 端口

### 4. 访问前端页面

直接在浏览器打开 `demo.html`，即可开始问答交互。

## 🧩 核心功能说明

### 1. 三级混合检索机制

- **稠密向量检索**：基于 bge-m3 生成的稠密向量，捕捉深层语义与隐含关联，擅长长文本语义匹配
- **SPLADE 稀疏检索**：语义级词权重匹配，兼顾关键词精准性与同义词、转述表达的语义泛化能力，全面替代传统 BM25
- **Reranker 精排**：对两路召回结果合并去重后，使用交叉编码器精细化打分排序，输出最相关的上下文片段

### 2. 双记忆体系

- **短期记忆**：内存存储最近 N 轮对话，随服务重启清空，用于保障单轮会话的上下文连贯性
- **长期记忆**：问答对持久化存入独立向量库，按 `session_id` 会话隔离，支持跨轮次语义回溯
- 提供独立接口，可分别清空短期会话记忆与全部长期记忆

### 3. 幻觉抑制机制

- 系统提示词刚性约束：回答仅允许使用参考资料原文信息，无相关内容时固定返回兜底话术
- 禁止模型使用自身固有知识编造细节，严格贴合原文措辞输出
- 指代类问题优先匹配会话历史，避免跨文档、跨会话信息串扰

### 4. 参考来源溯源

回答生成前先推送参考文档的文件名与页码，前端可展示引用来源，支持内容核验。

## 📊 效果评估

项目内置 `test_recall.py` 测试工具，可批量对比不同检索策略的召回率，验证优化效果：

```
python test_recall.py
```

支持自定义测试用例，输出纯向量检索与混合检索 + 重排的召回率对比数据。



## ⚙️ 常用配置调整

均可在 `sse_server.py` 顶部直接修改：

- `MAX_HISTORY_ROUNDS`：短期记忆保留轮数
- `SPLADE_BATCH_SIZE`：稀疏向量批量生成大小，根据显存调整
- `top_k`：粗排、精排返回片段条数
- 模型名称、服务端口、Ollama 地址等

## 📝 注意事项

1. 首次启动会自动下载 SPLADE 与 Reranker 模型，需保持网络通畅
2. 新增 PDF 文档后需重新执行 `ingest.py` 并重启后端服务，稀疏索引才会更新
3. 中文知识库建议替换为中文优化版 SPLADE 模型，可获得更优检索效果
4. 请勿直接上传 `chroma_db/` 与 `docs/` 目录到公开仓库，避免知识库内容泄露
